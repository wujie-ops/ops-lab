# 云服务器初始化与 ops 用户配置

- **创建**：2026-09-23 ｜ **更新**：2026-09-23
- **标签**：`#基础设施` `#linux` `#ssh` `#初始化`
- **适用范围**：新建 Linux 主机（Ubuntu 22.04）
- **验证状态**：✅ 已在阿里云 Ubuntu 22.04 实例上验证

## 结论先行

新主机开通后固定做四件事：

① 创建非 root 用户
② 配置 SSH 密钥登录 

③ 关闭 root 密码登录与密码认证 

④ 验证新用户可登录且root 不可直连。**核心目的是取消 root 直连、用带审计痕迹的具名账号 + 密钥认证。**

## 操作步骤

### 1.设置主机名

目前暂定 `dev`:

```bash
hostnamectl set-hostname dev
```

### 2. 创建 ops 用户（UID 2000）

创建 `ops` 用户、`/home/ops` 目录，指定 UID=`2000`，指定登录 `/bin/bash` 

```bash
sudo useradd -m -u 2000 -s /bin/bash ops
sudo passwd ops
sudo usermod -aG sudo ops
```

* 注意：Ubuntu 发行版的 管理员组 是 `sudo` ，其它发行版通常为 `wheel`

检查

```bash
~$ id ops
uid=2000(ops) gid=2000(ops) groups=2000(ops),27(sudo)
# 
~$ getent passwd ops
ops:x:2000:2000::/home/ops:/bin/bash
```

### 3.设置密钥

为 ops 用户添加一条 SSH 公钥，并设置文件 属主和权限：

```bash
# 创建 authorized_keys 文件，注意：路径为 /home/ops/.ssh
echo 'ssh-ed25519 AAAAC3Nza...' | sudo tee -a /authorized_keys
# 设置 文件属组
sudo chown ops:ops /home/ops/.ssh/authorized_keys
# 设置 文件权限
sudo chmod 600 /home/ops/.ssh/authorized_keys
```

注意：

* 这里采用的是手动创建并写入 `authorized_keys` 的方式，也可以采用其它方式，如文件上传、复制；
* 错误的属组 与 宽松的权限 可能会导致 公钥 被拒绝使用，无法用于远程登录。

检查

```bash
# 检查公钥
~$ sudo cat /home/ops/.ssh/authorized_keys # 使用 cat 输出到控制台
ssh-ed25519 AAAAC3Nza... # 检查是否为期望的公钥
# 检查文件权限与属组
~$ ls -l /home/ops/.ssh/authorized_keys # 查询文件属性 预期："rw-------"与"ops"
-rw------- 1 ops ops 101 Sep 24 19:20 /home/ops/.ssh/authorized_keys # 核对文件权限与属组
```

### 4.测试登录

```bash
ssh -i "私钥文件" ops@<host ip> # 进入会话
```

### 5.SSH加固

**目标操作：**关闭 root 密码登录与密码认证

**风险提示：**

* 对于云主机，这部分操作失误，可能会导致无法连接主机。
* 请确保在 root 用户无法远程登录的情况下（至少一个）
  * 有可用的救援方式
    * 服务商的 **VNC远程连接**
    * 服务商其它可用救援方式
  * 可密钥远程登录的 sudo 权限用户

**可选步骤**：

检查 `/etc/ssh/sshd_config.d` 目录下是否存在其它配置文件。全新环境通常没有，其它情况需要检查，如果存在需要审查**文件冲突**与**配置冲突**。

**开始：**

新建文件并写入参数：

```bash
sudo tee /etc/ssh/sshd_config.d/99-hardening.conf >/dev/null <<'EOF'
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
EOF
```

设置文件 属组与权限

```bash
sudo chown root:root /etc/ssh/sshd_config.d/99-hardening.conf
sudo chmod 644 /etc/ssh/sshd_config.d/99-hardening.conf
```

检查

```bash
# 命令
sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication|pubkeyauthentication'

# 预期输出
permitrootlogin no
passwordauthentication no
pubkeyauthentication yes
```

重启 SSH 服务

```bash
sudo systemctl reload ssh
```

### 6.测试

```bash
# 测试密码连接
~$ ssh root@<host ip>
root@<host ip>: Permission denied (publickey). # 预期输出
~$ ssh ops@<host ip>
ops@<host ip>: Permission denied (publickey). # 预期输出
~$ ssh -i "私钥文件" ops@<host ip> # 进入会话 输出 ops
```

## 操作目的

root 用户远程登录与密码验证登录 安全等级较低，通常会选择密钥方式。规范的设备名与用户设计，是高效管理的基础。

## 常见问题

* 新实例在配置初始化时，通常没有设置冲突，出现不符合预期的配置，通常时操作错误，每一步操作是注意检查。
* 对于配置用户时，发生失误，如不符合预期的用户名、UID，请参见《用户管理》--待定
* 对于密钥部分，请请参见 [002-SSH密钥生命周期管理.md](002-SSH密钥生命周期管理.md) 

## 补充资料

### 新增目录相关

```bash
# 命令
sudo useradd -m -u 2000 -s /bin/bash ops

# 效果
uid=2000(ops) gid=2000(ops) groups=2000(ops)
                     ↑
                 同名、同id组
```

命令作用：

* 创建了用户 user（UID 1001）
* 创建了组 user（GID 1001），并把它设为该用户的主组（primary group）

这是**"默认拒绝、按需授权"** 的设计思路；

对于需要共享（多人操作）的文件，需要预设计 权限，才可实现 多人边编辑。
